# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

TankAttack is a Unity 6 third-person tank **defense game** (editor `6000.5.10f1`). The player drives a yellow Original tank and defends the `EnergyCore` on an island against 5 waves of red tanks that arrive over two bridges. Code comments are in Korean; match that when editing existing files.

- **Render pipeline: Built-in.** No render pipeline asset is assigned, so URP shaders render pink. Create materials with the `Standard` shader. The URP package is installed but unused.
- **Input: legacy `Input` API** (`Input.GetAxis`, `Input.GetMouseButton`). The Input System package is installed at **1.20.1** because 1.13.0 does not compile on 6000.5; no game script uses it.
- `com.unity.ai.navigation` 2.0.16 is installed (NavMesh + `NavMeshLink`).
- There is no CLI build, lint, or test setup. Open the project in the Unity Editor and press Play. No `.asmdef` files exist; all game scripts compile into `Assembly-CSharp`.

## Testing policy

**The user does all testing and play-testing. Claude must not run tests.** Do not enter play mode, drive the player or enemies with scripted input, run auto-walk or stress scripts, or capture play-mode screenshots to verify a change. After an edit, only confirm that it compiles (no console errors) and tell the user what changed and what to check by hand. Read-only inspection of assets and scene values through MCP is still fine. This overrides the play-mode testing tips in "Tooling notes", which remain only as reference for when the user explicitly asks for a test run.

## Gameplay architecture

**Teams.** `TeamConfig.playerTeam = Team.Yellow` (allies); red is the enemy. Allies have 3x HP (`allyHpMultiplier`), enemies deal 0.6x damage. Base tank HP is 100. `TeamMember` (team, `isStructure`, static `All` list) must be on everything that can be shot; call `SetTeam` after `Instantiate`, which also refreshes `Health`. Projectiles and mines only affect the opposing team.

**Tanks.** Every tank prefab has `TeamMember`, `Health`, `HealthBar`, `TankInfo` (kind, speed, stop distance, flying), a `BoxCollider` for hits, and (gun tanks) `TurretAimer` + `TankShooter` + `AITurretCtrl`.
- `TurretAimer` rotates the turret parts (`turretParts`, including `FirePos`) around a `hub` point with yaw/pitch limits. It cannot reparent because the turrets are inside FBX model instances.
- `TankShooter` instantiates `projectilePrefab` (falls back to `Cannon`) and calls `Projectile.Init(team)`. If `allyProjectilePrefab` is set and the shooter's team is an ally, that prefab is fired instead (the UFO tank prefab is shared by both teams: enemy fires `Proj_UFO_Pink`, ally fires `Proj_UFO_Yellow`).
- `Projectile` kinds: `Armor` (fast straight), `Shell` (splash), `Ball` (bounces, frozen Y), `Plasma` (homing; targets enemy tanks, then structures if `attackStructures`). In `Start` it adds a per-kind colored `TrailRenderer` (`trailColor` overrides; Plasma also gets a point `Light`). On hit it instantiates `expEffect` 0.3 m above the point, **plays every `ParticleSystem` and `AudioSource` itself** (Tanks-sample explosion prefabs have Play On Awake off, so merely instantiating shows nothing), optionally scales particle size/speed by `expEffectScale` (Transform scale does not scale particles), and destroys it after 3 s. `Ball` spawns `bounceEffect` on each bounce (max 5 bounces, 35 m/s). `tintByTeam` (on `Proj_Armor`, `Proj_Shell`) colors the projectile body and trail by the shooter's team (enemy red, ally yellow); Ball, Plasma and UFO bombs keep their own colors. `Projectile.All` lists flying projectiles (used by UFO dodging). `expEffectScale` is 0.5 on Armor/Shell/Ball/Plasma and 2 on `Proj_UFO_*` (UFO effects stay the largest). UFO bombs/plasma have `turnSpeed` 360 and speed 24 so they hit more often; the UFO tank `AITurretCtrl.aimTolerance` is 15.
- `AITurretCtrl` only picks targets it can see from the turret hub (terrain, props and water block), fires only when the muzzle is not inside a collider and the line of fire is clear, and leads moving targets for straight projectiles (Armor, Shell).
- Ranges: `AITurretCtrl.range` Original 140, Heavy 80, MegaBall 50, UFO 80 (Original and Heavy were lowered by 20 m); `TankInfo.stopDistance` (stop-to-shoot distance) Original 20, Heavy 35, MegaBall 20, Light 3, UFO 25.
- MegaBall prefab: body (`ball`, `areial`, `barrel end`, `barrel`) uses the `TankColor 4` material so `TeamMember` colors it (enemy pink via `redColor`, ally yellow); the lid (`Topshpere`) uses `TankLidGray.mat` and stays gray.
- Per tank: Original = armor shots, Heavy = splash shell every 8 s (shell 40 m/s), MegaBall = bouncing ball, UFO = flying homing plasma, Light = no gun, drops `Mine` via `MineLayer` (the mine is tinted by the layer's team in `Mine.Init`: enemy red, ally yellow). `Alternative` is the legacy mouse-aim tank (`MouseTurretCtrl`).
- `GroundAlign` tilts ground tanks to the terrain normal in `LateUpdate`. With `frontBackOnly` (set by `PlayerTankController.Awake`, so only the player) it measures ground height 1.5 m (`probeDistance`) in front of and behind the hull and tilts pitch only (no roll, no pull from side slopes); it also exposes `forwardSlope` (height difference / distance) for the player's movement.
- `HealthBar` is a world-space bar (quads + `TextMesh`) on the core, gates and tanks (`textInside` puts the text inside the bar; used by the player, bar height 0.35). Its quads live under a separate root, so `OnDisable`/`OnEnable` hide/show that root (a destroyed gate disables its bar).

**Player.** `PlayerSpawner` (scene object) spawns `Tank_Player_Alternative` (the Alternative model with CharacterController; `Tank_Player_Original` is unused, Original tanks come only from ally spawns) in front of the building and respawns it 5 s after death. The prefab uses a `CharacterController` instead of the `BoxCollider`. `PlayerTankController`: W/S move (`moveSpeed` 13, `reverseSpeed` 7), A/D rotate. Movement keeps the horizontal direction untouched and only adds a vertical term from `GroundAlign.forwardSlope` (clamped to the `CharacterController.slopeLimit`, 50 deg) so the tank follows slopes without being pulled sideways. The `CharacterController` capsule `center` is re-derived every frame (`KeepCapsuleUpright`) because it rotates with the hull and drifted about 0.6 m sideways when the hull tilted. `ShoreBlocked` checks the hull center plus a 0.8 m lead point, and skips the lead point on bridge decks and bridge entrances (grid value 255), because the decks are only about 3 m wide and a slightly angled hull used to be blocked by the water cells beside the deck. `ThirdPersonCamera` is on `Main Camera`: with `followHull` (default) it stays behind the hull (`distance` 20, `pivotHeight` 5.5, fixed 18 deg pitch) and looks where the hull faces; the mouse does not move it (turn with A/D). With `followHull` off the mouse orbits. The camera position and yaw follow the player **instantly** (no lerp). At start the camera is placed once behind the player and **holds still until the player gives W/S/A/D input** (or is pushed more than 3 m). The cursor is locked (Esc releases, click relocks). **Aiming is a free screen cursor:** `PlayerTurretCtrl` moves a virtual crosshair on screen with the mouse (`cursorSpeed`, pixels per mouse axis unit at 1080p height, clamped to the screen), casts a camera ray through it (starting at the tank's depth so objects between camera and tank do not block it; `ThirdPersonCamera.RaycastIgnoringPlayer` skips the player, `Projectile` and `Mine`), and snaps the turret to that point with `TurretAimer.SnapTo` (instant, no `yawSpeed` lag). The turret is limited to `yawLimit` (60 deg) left and right of the hull front, set on `TurretAimer` in `Awake`; pitch uses the prefab limits (-20..35 deg), so the crosshair can sit outside the reachable range and the turret stops at the limit. Left mouse fires along the muzzle. `ThirdPersonCamera.OnGUI` draws the crosshair at `CursorPos` (`UseCursor`); `AimPoint` is the world point under it. The scene `Main Camera` has a pre-existing Missing Script component; leave it.

**Waves.** `WaveManager` runs 5 waves (`FillDefaultWaves` / inspector `Waves`, each with enemy `entries` per gate and ally `allies` auto-spawned at the building at wave start). W1 is 2 Original from Gate A only, player alone (tutorial); W2 to W5 add allies and mix Heavy, Light, UFO, MegaBall from both gates. W2 spawns 2 Heavy allies (one per bridge post). Speed grows 8% per wave. It tracks only the enemies it spawned. **Victory** needs both gates destroyed AND no enemy alive (checked in `Update`); clearing the last wave alone does not win (state stays Fighting until both gates are down). Defeat is the core `Health.onDeath`. The scene's `Waves` list is serialized, so edit wave contents in the inspector or via script as well as in `FillDefaultWaves`.

**HUD.** `GameHUD` (IMGUI, auto-added to the WaveManager object in `Start`) draws wave/enemy count/next-wave countdown and the core bar (top center), gold with a coin icon and floating +/- amounts (top right), the ally upgrade level, a kill gauge bar (`n / KillsPerLevel`) and the next level's reward text (`Lv3 : 공격력 +15%, 체력 +20%`), and active item buffs with icon and timer bar (bottom left; the player's HP is in the world-space bar above the tank), stacked toasts such as item pickups (`GameHUD.Pickup`, `GameHUD.Toast`) and the victory banner (defeat is shown by the Ending scene). `MapView` (self-creating, key **M**) toggles a top-down orthographic overview camera (center -135,150,90, size 140) with team marker dots drawn in IMGUI; while it is open `GameHUD`, `ShopUI`, `NoticeUI` and the crosshair hide and `PlayerTurretCtrl` stops aiming/firing (`MapView.IsOpen`). `ShopUI` draws the bottom buttons (key, name, price; dimmed when unaffordable or capped) and reports failures through `GameHUD.Toast`. `NoticeUI` (self-creating) shows the big top banner, e.g. "Gate B DESTROYED +150G". Everything scales with `Screen.height / 1080`. IMGUI is not captured by camera renders; use `ScreenCapture.CaptureScreenshot` in play mode to see it.

**Economy.** `GoldWallet` (static) holds gold plus all reward/cost numbers (kill reward per kind, wave bonus, summon cost, repair, upgrade). `ShopUI` (on the WaveManager object, IMGUI): keys 1-5 summon Original/Heavy/UFO... (see `summonKinds`), R repairs the core. Ally upgrades are **not bought**: every enemy kill (`WaveManager.HookKillReward` -> `AllyUpgrades.AddKill`) fills a gauge, and each `AllyUpgrades.KillsPerLevel` (8) kills gives a level (+15% damage, +20% HP per level, max 5, applies to the player too; existing allies' max HP is rescaled and a toast is shown). `AllySpawner.maxAllies` caps purchases. Enemy kills also drop random `ItemPickup`s (`WaveManager.itemDropChance`, 50%, serialized in the scene): Damage, FireRate, Speed (timed, via `PlayerBuffs` on the player) and Heal. Gold is only a HUD currency (kill/wave/gate rewards); it is not a pickup.

**Target priority.** `TankInfo.PrefersCore` (Original/Heavy/MegaBall): enemy goes straight to the core and `AITurretCtrl` shoots the core first. Light/UFO hunt the nearest ally tank anywhere (`EnemyMover.aggroRadius`, `FlyingMover`), core only as fallback.

**Spawn gates and enemy movement.** `SpawnGate.Spawn(prefab, hpScale, speedScale, sizeScale)` creates an enemy and adds a mover.
- Ground enemies use `EnemyMover`: first follow `Route` waypoints (roads and bridges) with **no NavMesh**, because the bridges have collider and NavMesh gaps. The waypoints are rounded into a quadratic Bezier path (`EnemyMover.SmoothPath`, `cornerCut`) so corners are curves. Tanks stop when another tank is ahead (`followGap`, 5 m). **MegaBall** (`EnemyMover.wander`) does not drive in a line: on roads `RoadWeaver` weaves it left/right inside the measured road width (it overtakes the tank ahead when offset), on the island it roams random points within 40 m of the core's approach point. At the end of the route a `NavMeshAgent` is added; the tank chases the nearest ally tank within `aggroRadius` or goes to the core's `ApproachPoint`.
- UFOs use `FlyingMover` (straight line over the lake). They hover `flyHeight` (6 m) above their **target tank** (not above the core, which floats ~20 m up), eased at 8 m/s, so the player can see and shoot them; when the target is the core they use the ground under it (`FlyUtil.GroundY`). Ally UFOs (`AllyMover.FlyUpdate`) do the same over their target. When the target is another UFO, both sides use `AirDodger` instead: face the target, keep 12 to 26 m, strafe left/right/up/down with random changes and sidestep incoming enemy projectiles (`Projectile.All`). If the UFO cannot see its ground target (`HasSight`) it keeps closing in instead of stopping.
- Route waypoints are children of `Gate A/Route`, `Gate B/Route`. Never hand-edit them: after moving, rotating or raising a bridge run the menu **TankAttack/Rebuild Gate Routes** (`Assets/Editor/GateRouteBuilder.cs`). It fits `Bridge Deck Fill`, rebuilds both routes (road curve as a 25 m-radius arc every 3 m, 6 m-radius turn onto the bridge, deck points every 2 m at deck height, end 5 m inside the island), moves `HeavyPost_A/B` beside each bridge exit (to the right, off the enemy path, away from water and props; 1 m toward the bridge from the exit, scene posts were nudged forward by hand) and rebakes `ShoreZone`. Road layout constants are at the top of that file.

**Allies.** `AllySpawner` is on the `building` object (spawn point on the building's world -Z side). Only the first two Heavy allies (W2) take `HeavyPost_A/B` (beside each bridge exit) and stand there; a post is never refilled (`postTaken`). When its bridge's gate is destroyed the Heavy leaves the post, kills enemies within `detectRadius`, then sets `assault`. Every later Heavy has no post and assaults like the other ground allies. MegaBall allies weave on roads (`RoadWeaver`) and pick sideways goals when engaging on the island. Allies only stop to hold/shoot when they actually see the enemy (`HasSight`), otherwise they keep approaching. Every other ground ally has `AllyMover.assault`: it defends against enemies on the island first (island = `islandMin/islandMax` rect, bridge decks excluded, because the NavMesh now also covers roads and bridges), otherwise it walks to a bridge entrance, turns its NavMeshAgent off, follows the gate route in reverse to `gateStandOff` (18 m) before the gate spawn point, holds when enemy tanks are in range and shoots the gate. Allies alternate gates by spawn order. When its gate is destroyed it drives back, re-enables the agent and goes to the remaining gate. UFO allies fly at enemy tanks, then gates.

**Gates.** `SpawnGate` is not destroyed on death: `IsDestroyed` turns on, its renderers/colliders/`TeamMember`/`HealthBar` are disabled (routes stay usable), the player gets `GoldWallet.gateReward` (150), `NoticeUI` shows "DESTROYED" and `destroyEffect` (`FX_GateBlast`, set on both gates in the scene) spawns. `WaveManager` moves a destroyed gate's spawns to the other gate and skips them if both are down. Gates are hollow arches, so AI and homing plasma aim at the upper half of the gate collider, and `Projectile` sweeps a sphere from its last position each physics step (fast shells tunnel through thin mesh colliders otherwise).

**Canon and walls.** `Models/canon_001` carries `AutoCannon`: an ally fixed gun that turns its `canon` child toward the nearest enemy tank within `range` (50 m, measured from the base center), fires `Proj_Armor` every 1.5 s, returns to its rest rotation when idle, and ignores ground enemies that have crossed the bridge (`EnemyMover.CrossedBridge`). It, `wall`, `wall_001`, `wall_002`, `wall_002 (1)` have a `BoxCollider` and a carving `NavMeshObstacle` so tanks cannot pass.

**Shore.** `ShoreZone` (scene object) holds a baked distance-to-water grid (`Bake` context menu). Water = ground below a `Lake*` plane; deck = top surface is a `Bridge*` collider. Deck cells and land within `bridgeMargin` (5 m) of a deck are exempt, but water beside a bridge is not. `PlayerTankController` refuses moves that bring the hull center or a point 1.5 m ahead closer than `blockDistance` (3 m) to water, and its `LateUpdate` teleports the player to the nearest safe land if it is ever over water. Each bridge has a child `Bridge Deck Fill` BoxCollider that covers the gaps in the bridge mesh collider. Rebake `ShoreZone` after moving bridges, lakes or terrain.

**Props.** `PropGuard` (name prefixes Tree, Rock, House, Tent, Warehouse, Doghouse, Mill, Watch Tower, building, Car) tells whether the ground below a point is a prop. `PlayerTankController` refuses moves onto props, `NavUtil.SampleNearest` avoids prop-top NavMesh points (AI is kept off props by their Not Walkable modifiers). The terrain meshes are named `Cliff*`.

**Core.** `EnergyCore` is a yellow structure (HP 1000, no ally multiplier, not destroyed on death). `CoreAnimator` rotates and hovers it. The `building` has a `TeamMember` (structure), a `BoxCollider` and a `Health` with `redirect` = core, so hitting the building damages the core. Its child `ApproachPoint` is a ground-level target for pathing because the core floats above the building.

## Recent changes (read with the sections above)

- **Wave size.** `WaveManager.countMultiplier` (2) multiplies every enemy `gateA/gateB` count and every ally `AllyEntry.count` at spawn time; the serialized `Waves` list is unchanged. UFO kills drop no item (`HookKillReward`).
- **Core needs a crossing.** Ground enemies (`EnemyMover` present) cannot pick structures (core, building) as targets until `EnemyMover.CrossedBridge`; `AITurretCtrl.CanAttackStructures`. UFOs are exempt.
- **Route spacing.** Enemies (`EnemyMover.EngagedAhead`) and allies (`AllyMover.RouteUpdate`) stop on the route when a visible opposing ground tank is within `min(stopDistance + routeEngageMargin 8, routeHoldMax 28)`, so Heavy no longer stops 15 m earlier than others. Light never holds. Allies also keep `followGap` (5 m) behind a same-direction tank (`AllyMover.IsBlockedAhead`, oncoming and flying tanks ignored).
- **Light.** `EnemyMover.huntTarget` is kept until it dies (no 0.5 s retargeting); Light `stopDistance` 3.
- **Mines.** `Mine.Update` also detonates by distance (`triggerRadius` 2 m horizontal, 3 m vertical, flying tanks ignored) because the player's `CharacterController` did not raise trigger events.
- **UFO.** `FlyUtil.ClampAboveGround` keeps UFOs at least 4 m over terrain/water. `FlyUtil.Separation` pushes same-team UFOs apart (10 m). Velocity is smoothed (`AirDodger.accel`, `FlyingMover.chaseAccel`, `AllyMover.flyVel`); dodge speed is 0.8x move speed. Ally UFOs chase the nearest enemy tank on the whole map and only attack gates when no enemy tank exists.
- **Projectile.** `Ball` fires `ballAngleMin..ballAngleMax` (4..12 deg) to a random side per shot, and passes through same-team tanks (ignores their colliders and restores the pre-collision velocity). `AutoCannon` leads moving targets (`LeadPoint`, velocity estimated per frame).
- **MegaBall.** Ally MegaBall on an assault route does not hold at the gate stand-off: `AllyMover.BeginRoam/RoamOutside` turns the agent on and roams within `outsideRoamRadius` (60 m) of the route end, chasing enemy tanks that are not on the island; when the gate is destroyed it drives back to the route and retreats along it. The NavMesh between the island and the roads is only partial across the bridges (`PathPartial`), so MegaBall cannot leave the road/bridge by NavMesh. Enemy MegaBall on the island is unchanged (random points within 40 m of the core).
- **Gate effects.** `SpawnGate.blastScale` (4) scales `destroyEffect` (one shot, destroyed after 6 s); `smokeEffect` (`Polygonal Particles/.../Smoke01.prefab`, set on both gates) is scaled by `smokeScale` (10 in the scene; Smoke01 puffs are huge at scale 1, so small values barely show) and stays until victory (`SpawnGate.ClearEffects` from `WaveManager`). `ScaleEffect` forces `ParticleSystemScalingMode.Hierarchy` so the scale reaches the particles.
- **Lives.** `PlayerSpawner.maxLives` (3). Each player death costs one; at 0 there is no respawn and `WaveManager.Defeat(DefeatReason.PlayerDead)` runs (the core's `onDeath` calls it with `CoreDestroyed`; `WaveManager.defeatReason` keeps it). `PlayerSpawner.Lives/MaxLives` are static.
- **HUD.** All UI uses the military-HUD style (angular panels, thin lines, corner brackets, amber / alert-red / paper palette, no rounded cards). `MenuKit` (static, `MenuKit.cs`) holds the palette (`Ink`, `Paper`, `Dim`, `Amber`, `Alert`, `Line`), `Text` (fonts `TitleFont` = Black Ops One, `Bold`/`Medium` = Rajdhani; pass `null` for the default font, used for Korean because the new fonts have no Hangul), `TextOutlined`, `TextFit`, `TextWidth`, `Spaced` (fake letter spacing), `HudPanel`, `BlockBar` (segmented bar with trail), `Chip`, `KeyCap`, `Tag`, `Brackets`, `Shade`/`Wash`/`ScreenFrame` (menu backdrop), plus `MenuList` (keyboard/mouse menu) and `ScreenFader`. `MenuKit.A` is a global alpha multiplied into `Fill`/`Text`; `GameHUD`, `ShopUI` and `NoticeUI` reset it to 1 at the start of `OnGUI`. Restyled: `GameHUD`, `ShopUI` (all cards share one name font size, computed so the longest label `REPAIR CORE` fits), `NoticeUI`, `MapView` (legend panel, bracketed markers) and `UiKit.Crosshair` (amber dot, ticks, corner brackets, centered exactly on `CursorPos`). `UiKit` still has the older rounded helpers (`Panel`, `Bar`, `Heart`) and `UiKit.Button`. The core bar and kill gauge ease toward their value; the lives row (blocks) sits directly above the Lv card with buff rows stacked above it. Item toasts and the reward line are Korean (`NEXT : Lv4 공격력 +15%, 체력 +20%`). The Lv card and lives stay visible while the player is dead.
- **Intro, ending and scene flow.**

## Tooling notes

- Unity MCP is connected. Use `mcp__unity-mcp__Unity_RunCommand` (class must be `internal class CommandScript : IRunCommand`) and `Unity_GetConsoleLogs`. Calling a tool right after a script edit can fail with "Unity not detected" while the editor recompiles/reloads; wait for `Library/ScriptAssemblies/Assembly-CSharp.dll` to update and retry.
- `RunCommand` rejects `System.Reflection`, and `AssetDatabase.DeleteAsset` is blocked as a "user interaction". Delete files with the shell and let Unity refresh. `FindObjectsByType<T>()` takes no sort argument in this editor version.
- Unity objects do not work with `??`. Use an explicit `GetComponent`/`AddComponent` helper.
- **Play mode freezes when the Unity window loses focus** (`Application.runInBackground` is false). When testing through MCP, set `Application.runInBackground = true` and `Time.timeScale` at runtime (not saved to the project). Per-frame measurement is done by adding an `EditorApplication.update` handler from `RunCommand`.
- After editing a prefab through `PrefabUtility.LoadPrefabContents`, saved changes may not show on a stale `LoadAssetAtPath`; call `AssetDatabase.ImportAsset(..., ForceUpdate)` before verifying. Removing a component that others `[RequireComponent]` fails; remove dependents first.
- `.gitignore` excludes `Library/`, `Temp/`, `Logs/`, `UserSettings/`, `*.csproj`, and `*.sln`. Do not commit generated project files.
- `RunCommand` often reports `UNEXPECTED_ERROR ... Command was executed partially` only because the log is full of `Serialized files [version 9] before 2019.1 are deprecated` warnings (from `FixTanksGraphics` refreshing the asset database). Read the `[Log]` lines: if they show the expected output, the command worked. `Resources.GetBuiltinResource<Texture2D>("Default-Particle.psd")` fails here; take the texture from an existing particle material instead. `Object.GetInstanceID()` is an error (use the object itself as a dictionary key). `result.Log` does not support `{0:F1}` format specifiers.
- Asset Store packs use URP materials. To use a pack prefab in Built-in, switch the material shader to `Standard` (read `_BaseMap`/`_BaseColor` first, then set `_MainTex`/`_Color`) or build new `Standard` materials, and assign materials to a prefab from the saved asset path (not from a `LoadAssetAtPath` right after `CreateAsset`, which can return null). To preview a prefab, instantiate it far from the scene (for example at 5000,5000,5000), render it with a temporary orthographic camera into a `RenderTexture` and write the PNG to the scratchpad. For particles call `ParticleSystem.Simulate(t, true, true)` after `Stop`.
- Without a controllable window, play-mode tests with timing can be done by registering an `EditorApplication.update` handler from `RunCommand` that waits for a condition (for example a `ParticleSystem.time`) and then captures; screenshots of IMGUI need `ScreenCapture.CaptureScreenshot`.
- The `Assets/_TerrainAutoUpgrade/` terrain layer files are deleted in the working tree (part of the user's asset cleanup) but are intentionally not committed, because `05.Models/New Terrain.asset` still referenced them. Confirm before committing that deletion.
